# Planted defects of the recipe check

Classification: Restricted

Each folder below holds a small recipe with one planted defect. Running `venom recipe check` on a folder must report
findings of its own rule and no other rule (SC-002 of spec 014, proved by `cmd/venom/recipe/cmd_test.go`). The
specs directory is the repository's `docs/specs`, and every suite names the spec `014-web-mobile-recipes`.

| Rule | Folder | The defect |
|---|---|---|
| RC01 | `RC01/` | a testcase whose name starts with no scenario id |
| RC02 | `RC02/` | the same scenario id in two suite files (`first.yml`, `second.yml`) |
| RC03 | `RC03/` | a testcase named with an id that no scenario of the spec holds |
| RC04 | `RC04/` | a scenario id named only in a comment, with no testcase that starts with it |
| RC05 | `RC05/` | a testcase whose only assertion does not read the application |
| RC07 | `RC07/` | a tautological assertion beside a good one |
| RC08 | generated by the test | a credential-shaped text in a step: `cmd_test.go` copies `../clean/page.yml` into a temporary folder with a connection string with a password in the typed text, assembled from fragments, so no file of the repository holds it |
| RC09 | `RC09/` | a `navigate` whose address has a scheme and is not a template |
